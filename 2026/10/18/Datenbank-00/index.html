Transaktionen

Transaktionsbegriff(事务概念)

Definition:
Eine Transaktion ist eine Folge von Operationen, die eine Datenbank von einem konsistenten Zustand in einen anderen konsistenten Zustand überführt.

事务是一系列数据库操作，将数据库从一个一致状态转换到另一个一致状态。

ACID-Eigenschaften

原则 德语 含义
A - Atomicity Atomarität 全部执行或全部不执行
C - Consistency Konsistenz 事务前后保持数据库一致性
I - Isolation Isolation 并发事务之间相互隔离
D - Durability Dauerhaftigkeit 提交后的修改永久保存

Transaktionssteuerung(事务控制)

  • BOT: Begin of Transaktion, 开始事务
  • COMMIT: 成功结束事务并确认修改
  • ABORT: 中止事务并撤销其未提交的修改

Read/Write 操作:
read(A,x): 读取数据库对象A的值,保存到局部变量x
write(x.A): 把局部变量x的值写回数据库对象A

注意！:
局部计算 x := x+1 不会直接改变数据库,只有write才会写回。COMMIT则确认事务成功完成。

Probleme im Mehrbeutzerbertrieb (并发问题)

多个事务同时操作数据库时,可能出现四种典型问题

问题 关键解释 核心含义
Nonrepeatable Read Inkonsitentes Lesen 读取过程中数据从变化，导致读取结果不一致
Dirty Read Lesen nicht bestätigter Daten 读取其他事务尚未提交的数据
Phantom Problem Veränderung der Ergebnismenge 查询涉及的记录集合产生变化
Lost Update Verloren gegangene Änderungen 一个事务的修改被另一个事务覆盖

Nonrepeatable Read (PPT 10-11)

给出的完整性约束: A+B+C=0
T1希望计算: X=A+B+C

执行过程:

  1. T1读取A,保存到局部变量x
  2. T2修改数据库中的A,C,然后COMMIT
  3. T1继续读取B,C
  4. T1混合使用旧A和新C,结果不一致

T1 liest Daten aus unterschiedlichen Zuständen der Datenbank.

Dirty Read (PPT 12)

典型操作顺序:
w1(x) → r2(x) → a1

T1修改x后没有提交,T2就读取了修改后的x。之后T1ABORT,导致T2使用了后面被撤销的数据。

Merke: Lesen von nicht bestätigten Änderungen.
重点: Dirty Read 不要求T1最终一定Abort,读取时尚未提交就是关键。

Phantom Problem (PPT 13)

使用员工工资作为例子:
SELECT COUNT(*) into X
FROM Mitarbeiter;

T1统计到10人,因此x=10;
T2插入一名新员工并COMMIT;
T1执行:
UPDATE Mitarbeiter
SET Gehalt = Gehalt + 10000/x;
由于此时已有11人,但x仍然为10;
计划扣除10000,实际扣除11000

Merke: Die Menge der betroffenen Datensätze verändert sich.
符合条件的记录集合发生变化。

Lost Update (PPT 14)

数据库初始:
x = 10

两个事务均读旧值10,都计算出11
最终: x = 11
正确结果应该是 x = 12

Merke: Eine Änderung wird durch eine andere Transaktion überschrieben.
一个事务的更新被另一个事务覆盖。

Serialisierbarkeit (可串行化)

Seriell vs. Verschränkt

Begriff 中文 Erklärung
Seriell 串行执行 事务一个接一个完整执行
Verschränkt 交错执行 多个事务操作相互穿插
Serialisierbar 可串行化 执行效果等价于某一种串行执行

Definition:
Eine verschränkte Ausführung heißt serialisierbar, wenn ihr Effekt identisch zum Effekt einer Seriellen Ausführung ist.
交错执行如果与某一种串行执行效果相同，就称为可串行化。

数学补充:
如果有n个不同的事务，串行顺序数量为: n!

如果T1,T2分别有m、n个操作.并保持各自内部顺序,则所有合法排序数为:
$\binom{m+n}{n}$ = $\frac{(m+n)!}{m!n!}$

Das Read/Write-Modell

正式定义: T = P1P2…Pn
其中: Pi $\in$ {r(xi),w(xi)}

Vollständige Transaktion (完整事务) 必须以 Abort 或 Commit 结束:

T=P1P2…Pna oder T=P1P2…Pnc

Bsp.: T11 = r(A)w(A)r(B)w(B)c

符号 意思
T Transaktion,事务
n 操作读写总数
r(x) Read,读取对象x
w(x) write,写入对象x
a Abort
c Commit

Merke:

  • Pi的下标表示第i个操作
  • 局部加减运算在这个模型中被省略
  • 完整(vollständig)不代表一定成功,Abort也可以结束事务

Schedule (执行调度) (PPT 20)

Definition:
Ein vollständiger Schedule ist eine Folge von Datenbankoprationen, die die relative Reihenfolge der Oprationen jeder Transaktion erhält und alle beteiligten Transaktion vollständig enthält.
完整Sschedule是多个事务操作组成的序列,包含所有相关事务的完整操作，并保持多个事务内部操作的相对顺序。

Bsp.:
s = r1(x) r2(x) w1(x) r2(y) a1 w2(y) c2

这个schedule是完整的，因为T1以Abort结束，T2以Commit结束，而且各自内部顺序保持不变。

Schedule vs. vollständige Schedule

  • Schedule: 可以是完整执行序列的一个前缀(Präfix)
  • Vollständiger Schedule: 包含全部操作，每个事务均完整结束

Merke: Reihenfolge innerhalb einer Transaktion bleibt erhalten.
每个事务内部的相对顺序必须保持不变。
